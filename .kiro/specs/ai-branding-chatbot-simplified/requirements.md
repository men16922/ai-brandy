# 요구사항 문서 (시연 단순화 + 환경 구분 포함)

## 소개

AI 브랜딩 챗봇을 macOS + Docker 로컬 환경에서 실행하고, 필요 시 dev 환경(AWS)에서도 동작한다. 주요 기능은 상호명 추천 → 간판 생성 → 인테리어 추천 → 최종 보고서 PDF 순서로 진행된다. UI는 Streamlit 단계형 플로우로 구현한다.

## 워크플로 (5단계)

1. **정보 입력**: 업종/지역/평수 입력 (사진 업로드 선택)
2. **분석 요약**: 간단한 점수/레이더 차트 표시
3. **상호명 제안**: 3개 추천 → 선택 또는 재추천(최대 3회)
4. **이미지 생성**: 간판 3안(DALL·E/SDXL/Gemini), 인테리어 3안(DALL·E/SDXL/Gemini)
5. **보고서 생성**: PDF 다운로드 버튼 제공

## 요구사항

### 요구사항 1: 상호명 추천

**사용자 스토리:** 사용자로서, 업종과 지역에 맞는 상호명을 빠르게 추천받고 싶다.

#### 승인 기준

1. WHEN 사용자가 업종/지역/평수를 입력했을 때 THEN 시스템은 10초 이내에 3개 후보를 제공해야 한다
2. WHEN 상호명 후보가 표시될 때 THEN 각 후보는 간단 설명과 점수(발음/검색)를 포함해야 한다
3. WHEN 사용자가 재추천을 요청했을 때 THEN 시스템은 중복을 회피하여 새로운 3개를 제공해야 한다 (최대 3회)
4. WHEN 사용자가 상호명을 선택했을 때 THEN 선택된 상호명은 이후 모든 단계에 반영되어야 한다

### 요구사항 2: 간판 이미지 생성

**사용자 스토리:** 사용자로서, 선택한 상호명으로 다양한 스타일의 간판 디자인을 받고 싶다.

#### 승인 기준

1. WHEN 상호명이 선택되었을 때 THEN 시스템은 상호명 + 업종 + 지역 특성을 반영해 3안을 생성해야 한다
2. WHEN 간판 이미지를 생성할 때 THEN DALL·E, SDXL, Gemini 모델을 각각 사용해야 한다
3. WHEN 이미지가 생성되었을 때 THEN 각 안은 카드 형태로 표시되고 간단 설명을 포함해야 한다
4. WHEN 이미지 생성이 실패했을 때 THEN 시스템은 폴백 이미지를 사용해야 한다

### 요구사항 3: 인테리어 추천

**사용자 스토리:** 사용자로서, 선택한 간판과 조화를 맞춘 인테리어 디자인을 받고 싶다.

#### 승인 기준

1. WHEN 간판이 선택되었을 때 THEN 시스템은 선택 간판과 조화를 맞춘 3안을 생성해야 한다
2. WHEN 인테리어 이미지를 생성할 때 THEN DALL·E, SDXL, Gemini 모델을 각각 사용해야 한다
3. WHEN 인테리어 안이 표시될 때 THEN Plotly 색상 팔레트와 간단한 레이아웃/예산을 표시해야 한다
4. WHEN 인테리어 생성이 실패했을 때 THEN 시스템은 폴백 이미지를 사용해야 한다

### 요구사항 4: 보고서 생성

**사용자 스토리:** 사용자로서, 모든 선택 사항을 포함한 완성된 PDF 보고서를 다운로드하고 싶다.

#### 승인 기준

1. WHEN 모든 단계가 완료되었을 때 THEN 시스템은 PDF 보고서를 생성해야 한다
2. WHEN PDF 보고서가 생성될 때 THEN 다음 항목들을 포함해야 한다:
   - 최종 상호명
   - 간판 3안 (선택 표시)
   - 인테리어 3안
   - 색상 팔레트
   - 예산 범위
   - 분석 요약
3. WHEN 보고서가 준비되었을 때 THEN 다운로드 버튼을 제공해야 한다
4. WHEN 보고서 생성이 실패했을 때 THEN 오류 메시지와 재시도 옵션을 제공해야 한다

### 요구사항 5: 환경별 실행

**사용자 스토리:** 개발자로서, 로컬과 개발 환경에서 각각 적절한 서비스를 사용하고 싶다.

#### 승인 기준 - Local 환경

1. WHEN APP_ENV=local일 때 THEN 저장소는 DynamoDB Local + 로컬 S3 버킷(ai-brand-local)을 사용해야 한다
2. WHEN 보고서가 생성되었을 때 THEN PDF는 Chroma DB에 벡터화되어야 한다
3. WHEN 헬스체크를 호출했을 때 THEN DynamoDB Local과 Chroma 상태를 반환해야 한다
4. WHEN JSON 데이터가 필요할 때 THEN DynamoDB 기동 시점에 data/ 폴더의 JSON을 자동 삽입해야 한다

#### 승인 기준 - Dev 환경

1. WHEN APP_ENV=dev일 때 THEN 저장소는 AWS DynamoDB + AWS S3(ai-brand-dev)를 사용해야 한다
2. WHEN 보고서가 생성되었을 때 THEN PDF는 Bedrock Knowledge Base에 벡터화되어야 한다
3. WHEN 헬스체크를 호출했을 때 THEN DynamoDB와 Bedrock KB 상태를 반환해야 한다
4. WHEN JSON 데이터가 필요할 때 THEN DynamoDB 기동 시점에 data/ 폴더의 JSON을 자동 삽입해야 한다

### 요구사항 6: 로깅 & 안정성

**사용자 스토리:** 개발자로서, 시스템 동작을 추적하고 오류 시 안정적으로 복구하고 싶다.

#### 승인 기준

1. WHEN 시스템이 동작할 때 THEN 구조화된 로그로 실행/요청/오류를 기록해야 한다
2. WHEN API 호출이 실패했을 때 THEN 폴백 데이터/이미지를 제공해야 한다
3. WHEN 네트워크 오류가 발생했을 때 THEN 재시도를 수행하고 오류 메시지를 표시해야 한다
4. WHEN 시스템이 복구되었을 때 THEN 정상 동작을 재개해야 한다

### 요구사항 7: 성능

**사용자 스토리:** 사용자로서, 빠른 응답 시간과 명확한 진행 상황을 확인하고 싶다.

#### 승인 기준

1. WHEN 텍스트 응답이 요청되었을 때 THEN 5초 이내에 응답해야 한다
2. WHEN 이미지 생성이 요청되었을 때 THEN 30초 이내에 완료해야 한다
3. WHEN 전체 워크플로가 실행될 때 THEN 5분 이내에 완료해야 한다
4. WHEN 처리가 진행 중일 때 THEN 로딩 표시와 ETA를 제공해야 한다
